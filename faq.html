FAQ

Frequently asked questions

Can't find your answer here? Check the full documentation or ask in GitHub Issues.

Pricing & licensing

Do I need to pay for anything?

No. Slice Backup is free and open source (GPL v2 or later), and every feature is built in — there are no paid add-ons, license keys, or a Slice Backup cloud account. Cloud storage itself (S3, Dropbox, SFTP hosting, etc.) is billed separately by that provider under your own account. The settings screen links to each provider's pricing page.

Does Slice Backup send my data anywhere?

Only to destinations you explicitly configure: your own cloud storage, SFTP server, or Dropbox app; another WordPress site you created a transfer key for; your notification email address; or your webhook URL. Slice Backup does not send backup data to its authors.

Backups & restores

Do scheduled backups run if nobody visits the site?

Scheduled backups use WP-Cron, which WordPress normally triggers on site visits. For low-traffic sites, set up a real server cron job to call wp-cron.php every few minutes so the schedule keeps firing. The System tab will also warn you when a scheduled backup is running late.

Where are backups stored?

Temporary and local backup files live in wp-content/uploads/slice-backup-temp/. If cloud storage is configured, a copy is also stored in your configured bucket, SFTP folder, or Dropbox App folder.

Will I be logged out after a restore?

Usually, yes — a database restore replaces the site's users and session data, so existing sessions can become invalid. Log back in using an account from the restored site once the job completes. The restore process itself keeps running in the background regardless of whether you're logged in to watch it.

A restore went wrong — can I undo it?

Yes, as of 1.1.0. Restores stage changes and keep a safety copy of what was there before. Undo it from the Restore tab, or run wp slice-backup rollback undo. See Rollback & safety copy.

What if my site uses a different PHP version than the backup was made on?

Slice Backup checks plugin and theme compatibility against the destination's PHP version before activating anything. An incompatible plugin is deactivated (files kept); an incompatible theme falls back to a default theme. See Restoring & migrating.

Encryption

What happens if I lose the encryption passphrase?

An encrypted backup cannot be opened without its passphrase. Keep your encryption passphrase somewhere safe — Slice Backup cannot recover a lost one, by design: that's what makes the encryption meaningful.

Where is the passphrase stored?

If you save it in the plugin's settings, it's encrypted using your site's own WordPress security keys and never stored in plain text. You can instead avoid storing it in the database entirely by defining SLICE_BACKUP_ENCRYPTION_PASSPHRASE in wp-config.php.

Uninstalling

What happens to my backups when I delete the plugin?

Settings, scheduled tasks and temporary files are removed. Backup bundles are kept by default, and cloud backups are never deleted automatically. To also delete local bundles on uninstall, define SLICE_BACKUP_DELETE_BUNDLES_ON_UNINSTALL as true in wp-config.php before removing the plugin.
