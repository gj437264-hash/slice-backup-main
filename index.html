Back up and move big WordPress sites without hitting the memory limit

WP Bundle Migrator backs up, restores and migrates WordPress by streaming everything in small slices. Memory use stays flat whether the site is 50 MB or 100 GB.

Built around the four things that break migrations

Most failures come from the same few causes. Each one is handled in the design, not patched afterward.

The server runs out of memory

Plugins that load a whole archive or table into RAM crash on shared hosting.

Streams in 2 MB slices. Files and database rows move through file handles and HTTP sockets in fixed-size pieces, so memory use does not grow with the site.

Changing the domain corrupts data

Plain search-and-replace breaks serialized PHP strings, and unserializing them to fix it can run attacker-supplied code.

Rewrites URLs without unserialize(). A tokenizer recalculates string lengths, including multi-byte UTF-8 and emoji, and never executes site data. This closes the object injection risk (CWE-502).

The new server has a newer PHP

Moving from PHP 7.4 to 8.2 or later can crash the site on old plugin code.

Checks plugins before the site boots. The compatibility inspector scans plugin code against the destination’s PHP version, deactivates any plugin with fatal syntax in the database, keeps its files, and writes a conflict report. You get a working site and a list of what to fix.

Timeouts and half-finished downloads

Gateways cut long requests, and big downloads fail with “File incomplete”.

Resumable downloads with HTTP Range. Archives of 5 GB and more can be paused, resumed or fetched with a download manager, and output buffers are cleared so the server does not run out of memory while sending.

Everything else you need for a safe move

Multisite support

Migrate a whole network, or pull one subsite out as a standalone install with table prefixes rewritten for you (wp_3_ becomes wp_).

Restores that keep going

If an archive has a damaged entry, the extractor logs a warning, skips it, and restores everything else.

Hardened extraction

Every path is checked against a canonical jail on Linux and Windows, which blocks Zip Slip (CWE-22).

Flexible export scopes

Standard migration, complete turnkey clone with WordPress core, database only, media only, or a granular selection.

Hooks for developers

Tune the database chunk size with the wp_bundle_migrator_chunk_size filter, or run your own code after a restore with the wp_bundle_migrator_after_restore action.

Clean uninstall

Deleting the plugin removes its settings, options and temporary migration folders.

Planned for later releases

Version 1.0.0 covers migration, backup and restore. These modules are planned and are not in the current release. The plan is to build them into the core plugin, so there will be no add-on ZIPs to install or keep in step with updates.

Cloud storage

Send backups straight to S3-compatible storage (Amazon S3, Cloudflare R2, Google Cloud, Wasabi, MinIO), Dropbox, OneDrive or SFTP. You bring your own storage credentials.

A small built-in SigV4 signer replaces the AWS SDK, and multipart uploads keep memory low.

Scheduled backups

Automatic backups with grandfather-father-son retention: 7 daily, 4 weekly and 12 monthly copies. A disk quota limit stops backups from filling the host.

Runs on Action Scheduler, prunes old local and cloud copies, and sends Slack, Discord or email alerts.

Server-to-server transfer

Pair two sites with a one-time 32-character token and move the site directly between them, without downloading a large archive to your computer.

Data streams in chunks over an encrypted REST connection, and the domain is rewritten on arrival.

Encrypted archives

Protect backups with AES-256-GCM. The authentication tag detects any change to an archive, so a tampered file fails to restore instead of loading.

Keys come from your passphrase through PBKDF2 with 100,000 iterations, using PHP’s built-in OpenSSL.

Automate it with WP-CLI

Run exports and restores from a terminal, a CI job or a headless server. Replace the domain during import in the same command.

# Export the whole site
wp bundle export --scope=full

# Turnkey clone with WordPress core and database
wp bundle export --scope=turnkey_full --output=/var/backups/site-clone.zip

# Pull subsite #3 out of a network as a standalone site
wp bundle export --multisite-mode=subsite --subsite-id=3 --convert-standalone

# Export the database only
wp bundle export --scope=db_only

# Restore and swap the domain
wp bundle import backup.bundle.zip \
  --old-url="https://dev.local" \
  --new-url="https://production.com"

# List and delete archives in the local vault
wp bundle list
wp bundle delete backup.bundle.zip

Get started in four steps

  1. Download the .zip from the latest release.
  2. Upload and activate it in WordPress, then open Tools > WP Bundle Migrator.
  3. Export the site, then import the archive on a fresh WordPress install with a different URL.
  4. Hit a bug, memory spike or failed restore? Report it in GitHub Issues with your PHP version and host.
Good practice: keep a separate backup of any site before you migrate or restore, and try a new setup on staging first.
