Move big WordPress sites without hitting the memory limit.

WP Bundle Migrator backs up, restores and migrates WordPress by streaming everything in small slices. Memory use stays flat whether the site is 50 MB or 100 GB.

Download latest release View on GitHub

Free and open source under GPL v2 or later. Works with WordPress 5.8 to 6.7 and PHP 7.4 to 8.4.

Built around the four things that break migrations

Most failures come from the same few causes. Each one is handled in the design, not patched afterward.

  • The server runs out of memory

    Plugins that load a whole archive or table into RAM crash on shared hosting.

    Streams in 2 MB slices

    Files and database rows move through file handles and HTTP sockets in fixed-size pieces, so memory use does not grow with the site.

  • Changing the domain corrupts data

    Plain search-and-replace breaks serialized PHP strings, and unserializing them to fix it can run attacker-supplied code.

    Rewrites URLs without unserialize()

    A tokenizer recalculates string lengths, including multi-byte UTF-8 and emoji, and never executes site data. This closes the object injection risk (CWE-502).

  • The new server has a newer PHP

    Moving from PHP 7.4 to 8.2 or later can crash the site on old plugin code.

    Checks plugins before the site boots

    The compatibility inspector scans plugin code against the destination’s PHP version, deactivates any plugin with fatal syntax in the database, keeps its files, and writes a conflict report. You get a working site and a list of what to fix.

  • Timeouts and half-finished downloads

    Gateways cut long requests, and big downloads fail with “File incomplete”.

    Resumable downloads with HTTP Range

    Archives of 5 GB and more can be paused, resumed or fetched with a download manager, and output buffers are cleared so the server does not run out of memory while sending.

Also included

Multisite support
Migrate a whole network, or pull one subsite out as a standalone install with table prefixes rewritten for you (wp_3_ becomes wp_).
Restores that keep going
If an archive has a damaged entry, the extractor logs a warning, skips it, and restores everything else.
Hardened extraction
Every path is checked against a canonical jail on Linux and Windows, which blocks Zip Slip (CWE-22).
Flexible export scopes
Full site, database only, or a turnkey bare-metal clone that includes WordPress core.

Automate it with WP-CLI

Run exports and restores from a terminal, a CI job or a headless server. Replace the domain during import in the same command.

# Export the whole site
wp bundle export --scope=full

# Turnkey clone with WordPress core and database
wp bundle export --scope=turnkey_full --output=/var/backups/site-clone.zip

# Pull subsite #3 out of a network as a standalone site
wp bundle export --multisite-mode=subsite --subsite-id=3 --convert-standalone

# Restore and swap the domain
wp bundle import backup.bundle.zip \
  --old-url="https://dev.local" \
  --new-url="https://production.com"

Help test the beta

The plugin is not in the WordPress.org directory yet. Try it on a staging or local site first, not on a live one.

Before you start: take a separate backup of any site you test on, and report problems on GitHub Issues.
  1. Download the .zip from the latest release.
  2. Upload and activate it on a test site, such as LocalWP or a staging server.
  3. Export the site, then import the archive on a fresh WordPress install with a different URL.
  4. Report bugs, memory spikes or failed restores in GitHub Issues. Include your PHP version and host.
